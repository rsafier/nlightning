# test/ — agent guide

The xUnit v3 + Moq suite. There is one test project per src layer, plus cross-cutting spec-vector and Docker tests. Tests must never be referenced from src/.

## Layout
- `NLightning.Domain.Tests`: value objects, Money, FeatureSet (BOLT 9), TLV/BigSize models, payloads, CommitmentNumber, CommitmentTransactionModelFactory, BitReader/Writer, and the commitment state machine (`Channels/Commitments/`: exhaustive `HtlcStateTableTests`, per-rule tests named after the BOLT 2 plan matrix, and `CommitmentsTestKit.cs` with fake signer/verifier ports and the two-engine `CommitmentPair` that checks spec agreement and conservation after every signature; `CommitmentPairSimulator.cs` + `CommitmentSimulatorTests.cs` are the seeded random two-engine invariant harness: 500 seeds by default, the 10k-seed `[Trait("Category", "Long")]` test is `Explicit` and runs only with `-- xUnit.Explicit=only`).
- `NLightning.Application.Tests`: channel handlers (OpenChannel1, AcceptChannel1, FundingCreated, FundingSigned) and PeerManager. Moq-heavy.
- `NLightning.Infrastructure.Tests`: crypto providers (`#if CRYPTO_LIBSODIUM` / `#if CRYPTO_NATIVE`), transport (BOLT 8 states/services), TLV converters, MessageService, PeerService (`PeerServiceTests`: gossip/stfu/networks; `PeerServiceLifecycleTests`: init handshake/routing), PeerCommunicationService (`PeerCommunicationServiceTests`: ping limits/ping loop start/disconnect; `PeerCommunicationServiceLifecycleTests`: ping/pong, init timeout), PeerAddress.
- `NLightning.Infrastructure.Bitcoin.Tests`: builders, outputs (`Outputs/*OutputTests.cs`), output comparer, ECDH, signer, BlockchainMonitor. There are no `Transactions/` tests because the src `Transactions/*Transaction.cs` classes are commented out.
- `NLightning.Infrastructure.Serialization.Tests`: `Messages/*MessageTests.cs` (most wire messages, including the v1-open OpenChannel1/AcceptChannel1/FundingCreated/FundingSigned, with single- and multi-byte channel_type rows; AcceptChannel2 is `AcceptChannel2MessageTypeSerializerTests.cs`). `Helpers/SerializerHelper.cs` wires the real factories. `Vectors/BigSize.txt` holds the BOLT 1 vectors.
- `NLightning.Bolt11.Tests`: invoice model and one test file per tagged field.
- `NLightning.Daemon.Tests`: open-channel client handlers and FeeService (the `serial` collection).
- `NLightning.Integration.Tests`: `BOLT3/`, `BOLT4/`, `BOLT8/` and `BOLT11/` spec vectors. `Docker/` holds live bitcoind+LND tests (LNUnit: `AbcNetworkTests`, `ChannelOpeningFlowTests`) plus `PostgresTests`/`SqlServerTests` (container-backed migrate + peer round trip; their fixtures connect to the container's bridge IP, which is not routable from macOS Docker Desktop). `Persistence/` holds the shared `PersistenceRoundTrip` helper and the in-memory `SqlitePersistenceTests` (no Docker, runs in CI). There are also `Fixtures/` and `TestCollections/`. The BOLT 10 DNS test was removed with the commented-out `DnsSeedClient`.
- `NLightning.Tests.Utils`: a shared library, not a test project. It holds `Mocks/` (FakeFixedKeyDh, FakeHandshake*, FakeServiceProvider, FakeSha256, FakeTransport), `Vectors/` (AEAD, BOLT 3 Appendix B/C/D/F, BOLT 8 `InitiatorValidKeysVector`; the other BOLT 8 vectors live in `Integration.Tests/BOLT8/Vectors/`) and `PortPoolUtil` (ports 49100-49149).
- `BlazorTests/`: a WASM app plus Playwright tests. They build only with `-c Release.Wasm`/`Debug.Wasm`, and in practice only on linux-x64 because `src/NLightning.Infrastructure/Crypto/Providers/JS/package.json` pins linux-x64 esbuild/rollup.
- `Docker/custom_lnd`: the LND image that the Docker tests build.

## Adding a test (the common case)
1. Put the test in the project that mirrors the src layer, using the same folder path (e.g. `src/NLightning.Infrastructure/Protocol/Tlv/Converters/X.cs` maps to `test/NLightning.Infrastructure.Tests/Protocol/Tlv/Converters/XTests.cs`).
2. Use a file-scoped namespace `NLightning.<Project>.Tests.<Folder>`. Relative `using Domain.X;` directives go after the namespace line.
3. Name tests `Given_X_When_Y_Then_Z`, with `// Arrange / // Act / // Assert` sections. Pass `TestContext.Current.CancellationToken` to async APIs.
4. For a new wire message, add `test/NLightning.Infrastructure.Serialization.Tests/Messages/<Name>MessageTests.cs`. Copy `UpdateAddHtlcMessageTests.cs` and build the serializer through `SerializerHelper`.
5. Spec vectors: shared C# vectors go in `NLightning.Tests.Utils/Vectors/Bolt<N>*Vectors.cs`. Spec tests go in `NLightning.Integration.Tests/BOLT<N>/`. Any text/JSON vector file needs a csproj item with `CopyToOutputDirectory="PreserveNewest"` (Serialization.Tests globs `<None Include="Vectors\*.*" .../>`; Integration.Tests uses `<Content Include="BOLT11/Vectors/ValidInvoices.txt" .../>`, so add `<Content Include="BOLT4/Vectors/*.json" .../>` there).
6. If you need internals, check that the src project's `AssemblyInfo.cs` InternalsVisibleTo lists the test assembly. Domain.Tests, Application.Tests and Daemon.Tests are NOT listed (`src/NLightning.Daemon/AssemblyInfo.cs` names a stale `NLightning.Bolts.Tests`). Internal vectors in Tests.Utils are visible only to the assemblies in `test/NLightning.Tests.Utils/AssemblyInfo.cs`.

## Mocking conventions
- Moq cannot mock `Span`/`ReadOnlySpan` parameters. Use the Fake* class + virtual `byte[]` `ITest*` interface pattern in `Tests.Utils/Mocks`.
- For HttpClient, mock `HttpMessageHandler` with `.Protected().Setup("SendAsync", ...)` (see Daemon.Tests/Services/FeeServiceTests.cs).
- `FakeSha256` computes a real SHA-256 over the appended data by default; override its virtual `GetHashAndReset()` via Moq to force a fixed digest. `FakeServiceProvider` throws KeyNotFoundException for unregistered types.
- Tests that must run serially need `[CollectionDefinition(Name, DisableParallelization = true)]` plus `[Collection(Name)]`.

## Dependency rules
- Test projects may reference src projects and `NLightning.Tests.Utils`. Nothing in src/ may reference test projects.
- Tests.Utils references only Domain, Infrastructure and Infrastructure.Bitcoin. It transitively brings in LNUnit and Docker.DotNet. Serialization.Tests and Daemon.Tests do not reference it.
- `src/Directory.Build.props` does NOT apply here. Each test csproj declares net10.0 and Nullable itself; all also set `IsTestProject`. New test projects need `xunit.runner.visualstudio` (3.1.5) or `dotnet test` discovers nothing. `python3 scripts/check-sln-configs.py` (a CI step) fails when a `*.Tests` project lacks `IsTestProject` or the runner, or when a declared solution configuration has no mapping in `NLightning.sln`.

## Commands (repo root)
- All tests, as CI runs them (`.github/workflows/dotnet.yml`, minus logger/coverage flags): `dotnet build -c Release -p:MSBuildWarningsAsMessages=MSB4121 && dotnet test --no-build -c Release --filter 'FullyQualifiedName!~Docker'`
- One class: `dotnet test test/NLightning.Domain.Tests/NLightning.Domain.Tests.csproj --filter "FullyQualifiedName~NLightning.Domain.Tests.ValueObjects.BigSizeTests"`
- Application.Tests and Daemon.Tests run under `dotnet test` like the rest. The xunit v3 runner also works: `dotnet run --project test/NLightning.Application.Tests -- -class <FQN>` (or `-method '*Name*'`).
- Native crypto: repeat with `-c Release.Native`. Formatting gate: `dotnet format --verify-no-changes --exclude "**/BlazorTests/**"`.
- Docker tests (need the Docker daemon and internet on first build): `dotnet test test/NLightning.Integration.Tests --filter "FullyQualifiedName~Docker"`. The inbound test uses `HOST_ADDRESS`.

## Gotchas
- `!~Docker` is a substring filter, so keep Docker tests in `NLightning.Integration.Tests.Docker` and don't put "Docker" in other test names.
- Keep tests hermetic: no live DNS or internet outside the Docker namespace. `PeerAddressTests` HTTP cases resolve `localhost` for that reason.
- The Docker fixtures force-remove containers named miner/alice/bob/carol, build `../../../../Docker/custom_lnd` relative to bin, and share one regtest network across the `regtest` collection, so state carries over between tests. Always `PortPoolUtil.ReleasePort` in Dispose.
- Count tests from `dotnet test` output: 2146 non-Docker per config on `wip/fafo` @ `1a38360` (Domain 545, Serialization 352, Infrastructure 308, Integration 255 with 1 skip, Bolt11 252, Bitcoin 247, Daemon 109, Application 78). The fully commented-out files were revived or deleted (NL-177).

## Onion routing (BOLT 4) hooks
- BOLT 4 tests (ONION M1/M2): spec vectors in `Integration.Tests/BOLT4/` (`OnionVectorTests` for construct/peel, blinded-payment and blinded-onion-message chains; `HopPayloadVectorTests`; `Bolt4VectorLoadingTests`; `OnionServiceRegistrationTests`; `FailureOnionVectorTests` for M3 error onions against `onion-error-test.json` and `returning-errors-trace.json`, the inline BOLT 4 "Returning Errors" trace transcribed to JSON, loaded by `Bolt4Vectors.LoadReturningErrorsTrace`, which also keeps the per-hop attribution_data for M3b; `MalformedFailureConversionTests` for malformed conversion, channel_update embedding and origin interpretation end to end on the onion-error-test.json route) with the typed loader `Tests.Utils/Vectors/Bolt4Vectors.cs`; Sphinx in `Infrastructure.Bitcoin.Tests/Onion/`; onion model, TLVs, validator, failure codes, `FailureMessageTests`, `FailureMessageConversionTests`, `FailureChannelUpdateFactoryTests`, `MalformedHtlcValidatorTests` and `FailureInterpreterTests` in `Domain.Tests/Protocol/Onion/`; `FailureOnionServiceTests` (fake serializer, since Bitcoin.Tests does not reference Serialization) in `Infrastructure.Bitcoin.Tests/Onion/`; `HopPayloadSerializerTests` and `FailureMessageSerializerTests` in `Infrastructure.Serialization.Tests/Onion/`; hop-payload TLV converters in `Infrastructure.Tests/Protocol/Tlv/Converters/Onion/`; `OnionReplayCacheTests` and `HmacSha256Tests` in `Infrastructure.Tests`. Onion-adjacent wire tests: `Serialization.Tests/Messages/UpdateAddHtlcMessageTests.cs`, `UpdateFailMalformedHtlcMessageTests.cs`, `UpdateFailHtlcMessageTests.cs`. `route-blinding-test.json` is only loaded, not asserted (M5).
- New onion/failure vector tests go in `Integration.Tests/BOLT4/` with data in `Tests.Utils/Vectors/Bolt4*`. Hop-payload TLV converter tests go under `Infrastructure.Tests/Protocol/Tlv/Converters`, and ChaCha20/HMAC primitives under `Infrastructure.Tests/Crypto` (test both Release and Release.Native). Multi-hop forwarding can reuse `LightningRegtestNetworkFixture` (alice/bob/carol) in the Docker namespace.
- BOLT 3 state: `Bolt3IntegrationTests` asserts the Appendix B funding tx byte-for-byte and every Appendix C commitment tx (`AssertUnsignedTxEquals`, witness stripped) plus signatures. `Bolt3AppendixCVectors.ExpectedCommitTx1Htlc*Tx` hold the second-stage HTLC txs for commit tx 1, but the builder test is skipped for NL-056 (not implemented). `Bolt3AppendixFVectors` (anchors) drive a byte-exact commitment-tx Theory over all 9 Appendix F vectors (no HTLC second-stage vectors yet).
