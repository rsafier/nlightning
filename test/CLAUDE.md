# test/ — agent guide

The xUnit v3 + Moq suite. There is one test project per src layer, plus cross-cutting spec-vector and Docker tests. Tests must never be referenced from src/.

## Layout
- `NLightning.Domain.Tests`: value objects, Money, FeatureSet (BOLT 9), TLV/BigSize models, payloads, CommitmentNumber, CommitmentTransactionModelFactory, BitReader/Writer, and the commitment state machine (`Channels/Commitments/`: exhaustive `HtlcStateTableTests`, per-rule tests named after the BOLT 2 plan matrix, and `CommitmentsTestKit.cs` with fake signer/verifier ports and the two-engine `CommitmentPair` that checks spec agreement and conservation after every signature; `CommitmentPair` also logs each side's domain events (`AliceEvents`/`BobEvents`, with the step name) and has `Disconnect()`; `CommitmentsEventsTests.cs` covers N4-T4 events (incl. `IncomingHtlcSettled`) and `ChannelDomainEvents.DerivePending`; `CommitmentPairSimulator.cs` + `CommitmentSimulatorTests.cs` are the seeded random two-engine invariant harness (it also checks the event invariants after every step: lock-in once and before any removal, fail only when final, every event re-derivable from the persisted transition): 500 seeds by default, the 10k-seed `[Trait("Category", "Long")]` test is `Explicit` and runs only with `-- xUnit.Explicit=only`).
- `NLightning.Application.Tests`: channel handlers (OpenChannel1, AcceptChannel1, FundingCreated, FundingSigned, ChannelReady, and the N6-T1 normal-operation handlers through `Channels/Handlers/NormalOperationTestContext`: pure engine + fake crypto ports, persistence mocks that record the call order; `Channels/Harness/TwoNodeHarness`: two real `ChannelManager`s with real signers joined by in-memory outboxes, sending through the production `ChannelOperationsService` + `CommitScheduler` (no debounce; `PumpAsync` waits for both schedulers) and optionally the real `LocalOnlyHtlcSwitch` with a hand-written `ISphinxService` fake (Moq can't mock its span parameters), the N6-T4 proof, extended for N7 with link drops, crash-at-save restarts and backup restores (`Channels/Reestablish/ReestablishHarnessTests`, see the Application CLAUDE.md); the N6-T2 send side in `Channels/Services/ChannelOperationsServiceTests`, `CommitSchedulerTests` and `Channels/Switch/LocalOnlyHtlcSwitchTests`), PeerManager (`PeerManagerConnectTests`: two real peer managers over loopback, NL-239/NL-240) and `Gossip/ChannelUpdateServiceTests` (real `LocalLightningSigner`s for both ends). Moq-heavy. `Channels/Services/RealSigningCommitmentPair.cs` is a two-engine harness with **real** crypto: each node is built from `AddBitcoinInfrastructure()` + `AddCommitmentEngineServices()` with a Moq `ISecureKeyManager` (deterministic seed) and a Moq `IChannelMemoryRepository`, so the engine ports sign and verify real BOLT 3 commitments; `Commit(from)` records the txid signed and the txid verified for every commitment. Each `RealSigningNode.Events` logs the engine's domain events with the step that raised them. `Payments/` (ABCD W1-B) tests the payment core with real Sphinx onions: `PaymentsTestNode` builds one node from `AddSerializationInfrastructureServices` + `AddBitcoinInfrastructure` + `AddPaymentsServices` with a hand-written `TestNodeKeyManager` (node-key ECDH through NBitcoin; Moq cannot set up span methods) and an `InMemoryInvoiceDbRepository`; `ThreeHopPaymentTests` peels a 3-hop onion at each hop. This is why Application.Tests references `NLightning.Infrastructure.Serialization`. `Channels/Harness/ThreeNodeHarness` (ABCD W2-B) runs Alice → Bob → Carol, each a production `ChannelManager` + `ChannelOperationsService` + `CommitScheduler` + `HtlcSwitch` with real signers, real Sphinx and error onions, the gossip service (signed `channel_update`) and its own SQLite file (real migrations, `UnitOfWork` and repositories, which is why Application.Tests also references `NLightning.Infrastructure.Repositories` and `NLightning.Infrastructure.Persistence.Sqlite`); per-direction FIFOs pumped round-robin; `SwitchNode.SwitchSuspended` records events without handling them (a crash right after the persist); `RestartAsync(node)` reloads the node from its database (startup replay with every link down) and `ReconnectAsync(node)` / `Disconnect(a, b)` + `ReconnectLinkAsync(a, b)` stand in for N7: they only call the production (decorated) `IPeerLivenessProbe.MarkLinkUp`, whose `LinkUpEventReplayer` replays `DerivePending` into the switch as in the daemon (`SwitchNode.ReplayPendingEventsAsync` is the manual replay for tests that un-suspend a switch); `Sent` logs every message with the sender's channel states; each node's `LockAudit` records any flow that takes a second channel lock; hooks: `SwitchNode.OnPublish` (every published message, right after its save), `AfterInvoiceRead` and `BeforeSetHtlcOrigin` (through `HookedUnitOfWork`, a wrapper of the production `UnitOfWork`). `Payments/Switch/ThreeNodeSwitchTests` is the W2-B proof (forward + immediate upstream fulfill, final-hop failure decoded at hop 1 after the irrevocable removal, malformed converted, fee_insufficient with Bob's signed update, restarts mid-forward with no lost or double fulfill, lock-in replay, pending circuit without an offer, two HTLCs for one invoice with the reads forced to interleave, the invoice settled in the fulfill's own save, a fulfill refused while the peer is away and sent once the link comes back (upstream and final hop, no restart), an offer that throws before or after its save; every archived row, incoming and outgoing, pruned).
- `NLightning.Infrastructure.Tests`: crypto providers (`#if CRYPTO_LIBSODIUM` / `#if CRYPTO_NATIVE`), transport (BOLT 8 states/services), TLV converters, MessageService, PeerService (`PeerServiceTests`: gossip/stfu/networks; `PeerServiceLifecycleTests`: init handshake/routing), PeerCommunicationService (`PeerCommunicationServiceTests`: ping limits/ping loop start/disconnect; `PeerCommunicationServiceLifecycleTests`: ping/pong, init timeout), PeerAddress.
- `NLightning.Infrastructure.Bitcoin.Tests`: builders, outputs (`Outputs/*OutputTests.cs`), output comparer, ECDH, signer, BlockchainMonitor. `Builders/HtlcTransactionBuilderTests.cs` covers the HTLC-timeout/success builder; there are no `Transactions/` tests because the remaining src `Transactions/*Transaction.cs` classes are commented out.
- `NLightning.Infrastructure.Serialization.Tests`: `Messages/*MessageTests.cs` (most wire messages, including the v1-open OpenChannel1/AcceptChannel1/FundingCreated/FundingSigned, with single- and multi-byte channel_type rows; AcceptChannel2 is `AcceptChannel2MessageTypeSerializerTests.cs`). `Helpers/SerializerHelper.cs` wires the real factories. `Vectors/BigSize.txt` holds the BOLT 1 vectors.
- `NLightning.Bolt11.Tests`: invoice model and one test file per tagged field.
- `NLightning.Daemon.Tests`: open-channel client handlers and FeeService (the `serial` collection).
- `NLightning.Integration.Tests`: `BOLT3/`, `BOLT4/`, `BOLT8/` and `BOLT11/` spec vectors. `Docker/` holds live bitcoind+LND tests (LNUnit: `AbcNetworkTests`, `ChannelOpeningFlowTests`, `NormalOperationFlowTests` (N0/N1 idle channels; N6-T5 `Given_LndPaysUs_When_LockedIn_Then_FailedBackAndChannelActive`: alice `BuildRoute` + `SendToRouteV2` with a random hash to us, we fail back `incorrect_or_unknown_payment_details` and LND reports it from index 1; the route carries no payment_addr because LND refuses to attach one for a node it has no features for), `MultiNodeHarnessTests`; our node is `Docker/Utils/NLightningTestNode`, built from the daemon's `AddNltgNodeServices` with a fixed fee answer, and restartable on the same key and database) plus `PostgresTests`/`SqlServerTests` (container-backed migrate + peer round trip; `PostgresFixture`/`SqlServerFixture` publish the database port on `127.0.0.1` and wait for a real `SELECT 1`, so they work on Docker Desktop as well as OrbStack). `Persistence/` holds the shared `PersistenceRoundTrip` helper, the in-memory `SqlitePersistenceTests` (no Docker, runs in CI), `ChannelRoundTripTests` (every `ChannelModel` field saved and reloaded through SQLite, both roles) and `ChannelMigrationDataTests` (runs the channel data steps of the Sqlite migrations on rows written with the older schema). There are also `Fixtures/` and `TestCollections/`. The BOLT 10 DNS test was removed with the commented-out `DnsSeedClient`.
- `NLightning.Tests.Utils`: a shared library, not a test project. It holds `Channels/TestChannelParams` (builds a `ChannelParams` with the same limits on both sides for tests that don't care about direction), `Mocks/` (FakeFixedKeyDh, FakeHandshake*, FakeServiceProvider, FakeSha256, FakeTransport), `Vectors/` (AEAD, BOLT 3 Appendix B/C/D (the Appendix C/F commitment and HTLC txs are spec text files in `Integration.Tests/BOLT3/Vectors/`), BOLT 8 `InitiatorValidKeysVector`; the other BOLT 8 vectors live in `Integration.Tests/BOLT8/Vectors/`) and `PortPoolUtil` (ports 49100-49149).
- `BlazorTests/`: a WASM app plus Playwright tests. They build only with `-c Release.Wasm`/`Debug.Wasm`, and in practice only on linux-x64 because `src/NLightning.Infrastructure/Crypto/Providers/JS/package.json` pins linux-x64 esbuild/rollup.
- `Docker/custom_lnd`: the LND image that the Docker tests build.

## Adding a test (the common case)
1. Put the test in the project that mirrors the src layer, using the same folder path (e.g. `src/NLightning.Infrastructure/Protocol/Tlv/Converters/X.cs` maps to `test/NLightning.Infrastructure.Tests/Protocol/Tlv/Converters/XTests.cs`).
2. Use a file-scoped namespace `NLightning.<Project>.Tests.<Folder>`. Relative `using Domain.X;` directives go after the namespace line.
3. Name tests `Given_X_When_Y_Then_Z`, with `// Arrange / // Act / // Assert` sections. Pass `TestContext.Current.CancellationToken` to async APIs.
4. For a new wire message, add `test/NLightning.Infrastructure.Serialization.Tests/Messages/<Name>MessageTests.cs`. Copy `UpdateAddHtlcMessageTests.cs` and build the serializer through `SerializerHelper`.
5. Spec vectors: shared C# vectors go in `NLightning.Tests.Utils/Vectors/Bolt<N>*Vectors.cs`. Spec tests go in `NLightning.Integration.Tests/BOLT<N>/`. Any text/JSON vector file needs a csproj item with `CopyToOutputDirectory="PreserveNewest"` (Serialization.Tests globs `<None Include="Vectors\*.*" .../>`; Integration.Tests uses `<Content Include="BOLT11/Vectors/ValidInvoices.txt" .../>`, so add `<Content Include="BOLT4/Vectors/*.json" .../>` there).
6. If you need internals, check that the src project's `AssemblyInfo.cs` InternalsVisibleTo lists the test assembly. Domain.Tests and Daemon.Tests are NOT listed (Application.Tests is) (`src/NLightning.Daemon/AssemblyInfo.cs` names a stale `NLightning.Bolts.Tests`). Internal vectors in Tests.Utils are visible only to the assemblies in `test/NLightning.Tests.Utils/AssemblyInfo.cs`.

## Mocking conventions
- Moq cannot mock `Span`/`ReadOnlySpan` parameters. Use the Fake* class + virtual `byte[]` `ITest*` interface pattern in `Tests.Utils/Mocks`.
- For HttpClient, mock `HttpMessageHandler` with `.Protected().Setup("SendAsync", ...)` (see Daemon.Tests/Services/FeeServiceTests.cs).
- `FakeSha256` computes a real SHA-256 over the appended data by default; override its virtual `GetHashAndReset()` via Moq to force a fixed digest. `FakeServiceProvider` returns null for unregistered types like the real provider (NL-249); `new FakeServiceProvider { Strict = true }` throws KeyNotFoundException instead.
- Tests that must run serially need `[CollectionDefinition(Name, DisableParallelization = true)]` plus `[Collection(Name)]`.

## Dependency rules
- Test projects may reference src projects and `NLightning.Tests.Utils`. Nothing in src/ may reference test projects.
- Tests.Utils references only Domain, Infrastructure and Infrastructure.Bitcoin. It transitively brings in LNUnit and Docker.DotNet. Serialization.Tests and Daemon.Tests do not reference it.
- `src/Directory.Build.props` does NOT apply here. Each test csproj declares net10.0 and Nullable itself; all also set `IsTestProject`. New test projects need `xunit.runner.visualstudio` (3.1.5) or `dotnet test` discovers nothing. `python3 scripts/check-sln-configs.py` (a CI step) fails when a `*.Tests` project lacks `IsTestProject` or the runner, or when a declared solution configuration has no mapping in `NLightning.sln`.

## Commands (repo root)
- All tests, as CI runs them (`.github/workflows/dotnet.yml`, minus logger/coverage flags): `dotnet build -c Release -p:MSBuildWarningsAsMessages=MSB4121 && dotnet test --no-build -c Release --filter 'FullyQualifiedName!~Docker'`
- One class: `dotnet test test/NLightning.Domain.Tests/NLightning.Domain.Tests.csproj --filter "FullyQualifiedName~NLightning.Domain.Tests.ValueObjects.BigSizeTests"`
- Application.Tests and Daemon.Tests run under `dotnet test` like the rest. The xunit v3 runner also works: `dotnet run --project test/NLightning.Application.Tests -- -class <FQN>` (or `-method '*Name*'`).
- Native crypto: repeat with `-c Release.Native`. Formatting gate: `dotnet format --verify-no-changes --exclude "**/BlazorTests/**"`.
- Docker tests (need the Docker daemon and internet on first build): `dotnet test test/NLightning.Integration.Tests --filter "FullyQualifiedName~Docker"`. The inbound test uses `HOST_ADDRESS`.

## Gotchas
- `!~Docker` is a substring filter, so keep Docker tests in `NLightning.Integration.Tests.Docker` and don't put "Docker" in other test names.
- Keep tests hermetic: no live DNS or internet outside the Docker namespace. `PeerAddressTests` HTTP cases resolve `localhost` for that reason.
- The Docker fixtures force-remove containers named miner/alice/bob/carol/david (`LightningRegtestNetworkFixture.ContainerNames`), build `../../../../Docker/custom_lnd` relative to bin, and share one regtest network across the `regtest` collection, so state carries over between tests: assert deltas, never absolute state. `david` is an LND node with no channels (the ABCD payee). Always `PortPoolUtil.ReleasePort` in Dispose (a node made with `NLightningTestNode.CreateAsync` does it itself).

## Multi-node Docker harness (`Docker/Utils/`, roadmap W0-F)
- `NLightningTestNode.CreateAsync(fixture, "bob", database?)` makes a node that owns a pooled port, a fresh `FakeSecureKeyManager` and a SQLite file (released/deleted in `DisposeAsync`), logs with a `[bob]` prefix and uses a 1 s reconnect backoff (`ReconnectInitialDelay`, applied as `NodeOptions.ReconnectInitialDelay`). Several nodes run in one process. `TestNodeDatabase.Sqlite/Postgres/SqlServer(...)` picks the provider; for a server database pass `PostgresFixture/SqlServerFixture.ConnectionStringFor(uniqueDbName)` (migrate creates it). `PostgresFixture.StartNamed`/`SqlServerFixture.StartNamed` start a private container for a `regtest`-collection test.
- `ConnectToAsync(LNDNodeConnection)` / `ConnectToAsync(NLightningTestNode)` (`pubkey@127.0.0.1:port`), `IsConnectedTo(nodeId)`, `CrashAsync()` (resets every socket through the `CrashableTcpService` decorator of `ITcpService`, so peers get no final message; then tears the services down; `StartAsync` restarts on the same key and database). `CrashAsync` is a crash on the wire only: the teardown is the graceful `StopAsync` (`PeerManager.StopAsync` waits for the inbound loops), so the database is flushed; a crash between persist steps needs a hook in the code under test.
- NLightning-to-NLightning connects must work the first time (NL-239 lost init and NL-240 simultaneous connect are fixed; the retry tolerance is gone). `ConnectToAsync(NLightningTestNode)` connects once and returns after both ends list each other and the connection stayed up for `ConnectionStableWindow` (1.5 s), else throws `TimeoutException`. `MultiNodeHarnessTests` proves it (5 rounds each of sequential connects in both directions and of simultaneous connects, each leaving exactly one live connection) and asserts that neither `InitLostLogFragment` nor `InitWriteFailedLogFragment` was ever logged. The in-process, non-Docker equivalent is `Application.Tests/Node/Managers/PeerManagerConnectTests` (two real `PeerManager`s over loopback with the real BOLT 8 stack and an in-process message serializer, 20 rounds each; it takes OS-assigned ports, not `PortPoolUtil`'s, because that pool is per process and other test projects listen on it at the same time).
- A failed `StartAsync` stops what it started and disposes the service graph; `StopAsync` disposes it even when a service fails to stop. `GetEfProviderName()` reports the EF provider the node really runs on. `LightningRegtestNetworkFixture.GetOrCreateAsync` (backed by `Fixtures/SharedObjectCache`) throws `InvalidOperationException` when a key is reused for another type.
- `Docker/ReestablishFlowTests` (Proof N7): a channel we open to alice survives (a) our restart, (b) `Builder.RestartByAlias("alice")` with its defaults (`isLND: false`, a plain container restart; `isLND: true` reopens alice's fixture channels and hangs in `WaitUntilAliasIsServerReady` when the address changed). Docker gives a restarted container the lowest free address of its network, so after an earlier test removed a container alice would move and every later test would lose her: the test first fills the free addresses below alice's with idle `nltg-address-hold-N` containers (removed after the restart) and asserts the address is unchanged. And (c) a wire crash (`CrashableTcpService.CrashAsync` from an `OnResponseMessageReady` handler, right after our commitment_signed is persisted) plus restart with LND's HTLC in flight; each ends reestablished (`IReestablishTracker`), Active in LND, no pending/waiting force close, and the HTLC failed back at 2/2.
- `Docker/ChannelSafetyFlowTests` (Proof N9, second half; N9-T2 + N9-T4): we pay an LND hold invoice (`cltv_expiry` 24), disconnect (LND cancels a held HTLC 12 blocks before its expiry while connected), mine to `cltv_expiry + 2`: our `HtlcExpiryMonitor` fails the channel, `ChannelFailureService` broadcasts our latest commitment (mempool, 4-item witness, the HTLC output), it confirms, our channel is `Closed` and LND lists it `RemoteForceClose` with our txid. Its second test forwards LND alice → us → LND david (hold invoice with a hint through our private channel, our `cltv_expiry_delta` 40): while david holds the HTLC the monitor fails no channel and leaves the incoming HTLC alone (circuit `Offered`, continued downstream); david gives up 12 blocks before the outgoing expiry and we fail back to alice at that height, before our fail-back height (`cltv_in - 40`) and the downstream deadline (`cltv_out + 2`); alice sees `incorrect_or_unknown_payment_details` from david (index 2) and both channels stay usable. The safety services are built by hand over `node.Services` until the integrator registers and starts them. If the host's `dotnet` gets "No route to host" to the container addresses (seen on this machine in wave 3), run the Docker tests from an SDK container on the bridge: `docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v <worktree>:/src:ro mcr.microsoft.com/dotnet/sdk:10.0` (copy /src without bin/obj, build, `dotnet test --filter ...`), or, faster, build on the host and run the host-built test assembly in the container with the worktree mounted at the same path: `docker run --rm --network bridge -v /var/run/docker.sock:/var/run/docker.sock -v <worktree>:<worktree> -w <worktree> mcr.microsoft.com/dotnet/sdk:10.0 dotnet test/NLightning.Integration.Tests/bin/Release/net10.0/NLightning.Integration.Tests.dll -class <Ns.Class> -showLiveOutput` (xunit v3 in-process; `dotnet test` on the dll fails because it launches the macOS apphost).
- `Docker/ChannelUpdateExchangeTests` (W1-E): opens a channel from an `NLightningTestNode` (custom `Routing` fee/CLTV) to alice and checks LND `GetChanInfo` shows that policy for our side and that our `IChannelUpdateService` stored alice's update (signature checked).
- `ChainSync.WaitAllAtTipAsync(fixture, nodes, ct)` / `MineAndWaitAsync(...)`: the barrier to call after every mine (every LND `synced_to_chain` at the tip, every node's `BlockchainMonitor.LastProcessedBlockHeight` at the tip; the timeout lists every height).
- `LndTestHelpers`: `HopHint`/`RouteHint` builders, `AddInvoiceAsync` with explicit route hints, `AddHoldInvoiceAsync`/`SettleInvoiceAsync`/`CancelInvoiceAsync`, `WaitForInvoiceStateAsync`, `PinnedPayment` (max_parts=1, pinned outgoing channels) + `SendPaymentV2Async` (returns the final update; don't await it to leave a payment in flight), `ResetMissionControlAsync`, `GetChannelByPointAsync`, `DisconnectPeerAsync`, `GetVersionAsync`.

## ABCD suite and N8 proofs (`Docker/Abcd/`, `Docker/NormalOperationFlowTests`, roadmap W2-D)
- `Docker/Abcd/` is the ABCD e2e suite of `docs/agents/ABCD_ROADMAP.md` §3 (LND alice → our bob → our carol → LND david). `AbcdNetwork` builds the topology once per fixture (`AbcdNetwork.GetAsync` → `fixture.GetOrCreateAsync("abcd-network")`, storing an `OnceOnlyBuild<AbcdNetwork>` so a failed build is cached too and every later ABCD test fails fast with the original error instead of opening more channels on the shared alice/david): bob and carol are `NLightningTestNode.CreateAsync` nodes with `AbcdPolicy.Bob` (1000 msat, 100 ppm, delta 40) and `AbcdPolicy.Carol` (2000, 500, 40); NLightning funds all three channels (B→A 2M sat with 1M pushed, B→C and C→D 2M sat, 10,000 sat/kw) and mines one block at a time (with `ChainSync`) until every end is usable. Test classes derive from `AbcdTestBase` (keep `[Collection(LightningRegtestNetworkFixtureCollection.Name)]` on each), whose `InitializeAsync` runs `PrepareForPaymentAsync` (restarts a node a failed test left stopped, waits for usable channels, no pending HTLC, chain tip) and whose `DisposeAsync` dumps every channel end, both node log tails and `docker logs alice/david` when the test failed. Assert deltas from `AbcdNetwork.SnapshotAsync` (`AbcdSnapshot`), never absolute balances; `AbcdPathFees.ToDavid(x)` is the BOLT 7 fee maths the payments must match. Mine only when no HTLC is in flight (the restart variants assert the tip did not move).
- Classes: `AbcdReestablishTests` (alice drops bob, carol drops bob + explicit reconnect (tolerates losing the race to bob's own reconnect), david drops carol, carol restart; sent `channel_reestablish` counted with `ChannelMessageRecorder`, received ones proven by `IsReestablished`), `AbcdPaymentTests` (happy path; variant a: canceled invoice → `incorrect_or_unknown_payment_details` from index 3), `AbcdRestartTests` (variant b2 with stop and crash, b1), `AbcdSendReceiveTests` (c-send: bob pays david through carol; c-receive: alice pays bob's invoice).
- `ChannelMessageRecorder` records what a node sends through `IChannelManager.OnResponseMessageReady`; `AbcdNetwork.StartNodeAsync`/`StopNodeAsync` re-attach it, so restart nodes through those. Received messages are not hooked (the peer services are created per connection).
- `NodeClientCalls` (extensions on `NLightningTestNode`): `CreateInvoiceAsync`, `PayInvoiceAsync`, `GetInvoiceAsync`, `GetPaymentAsync` (through `listinvoices`/`listpayments`), `GetChannelAsync`, `ChannelInfoClientResponse.IsUsable()` (Open, peer connected, `IsReestablished`), `ShortChannelId.ToUInt64()` (LND `chan_id`), `ChannelPoint()` (LND `txid:index`). Always go through the daemon's client handlers, not the services.
- `NormalOperationFlowTests` also holds Proof N8 (`Given_LndPaysOurInvoice_Then_Settled`, `Given_TrimmedHtlc_When_LndPaysOurInvoice_Then_Settled` (5,000 sat, trimmed on both commitments; asserted from LND's channel type, dust limits and feerate before paying), `Given_LndInvoice_When_WePay_Then_PreimageReturned`, `Given_ConcurrentPaymentsBothWays_Then_AllSucceed` (10 each way), `Given_InFlightRestart_Then_FulfillArrivesAfterReestablish`). They need the W2-B switch, the W2-C `PaymentService` and W2-A reestablish (`IsReestablished` true on a usable channel, also a freshly opened one).
- `scripts/run-abcd.sh [runs=3] [configuration=Release]` builds once, then runs `FullyQualifiedName~NLightning.Integration.Tests.Docker.Abcd` that many times, each in a fresh `dotnet test` process (fresh fixture), and stops at the first red run (TRX files in `TestResults/abcd/`).
- `Poll.UntilAsync`/`ForAsync` (returns the first non-null value)/`StaysTrueAsync`/`HoldsAsync` (returns false instead of failing) instead of fixed sleeps; `DockerDiagnostics.DumpContainerLogsAsync` in `DisposeAsync` when `DockerDiagnostics.CurrentTestFailed`.
- Count tests from `dotnet test` output: 3934 non-Docker per config at `a5675cb` after ABCD wave 2 (Domain 1236, Application 563, Integration 512, Serialization 466, Infrastructure 342, Bitcoin 305, Bolt11 275, Daemon 235), no skips; 47 Docker tests passed in the integrator's full run at `a5675cb` (including 4 container-free unit tests, `PollTests` and `Abcd/OnceOnlyBuildTests`, the N7 and N8 proofs and the ABCD cases). The fully commented-out files were revived or deleted (NL-177).
