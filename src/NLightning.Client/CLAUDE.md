# NLightning.Client (CLI for the daemon)

## Purpose
A console exe that sends **one IPC request per call** to a running `NLightning.Daemon` and prints the result. The help text calls it `nltg`, but no AssemblyName is set, so the binary is `NLightning.Client`. It has no Lightning protocol logic of its own. All work is done by the daemon.

## Layout
- `Program.cs`: top-level statements. Sets `MessagePackSerializer.DefaultOptions = NLightningMessagePackOptions.Options` (this must happen first), wires Ctrl+C and calls `ClientApp.RunAsync`.
- `ClientApp.cs`: checks `--help` first, validates the command and its argument count (`ValidateArguments`, exit code 2 on usage errors), resolves pipe and cookie paths, then dispatches on a `switch (cmd)` that accepts aliases (`info|node-info`, `connect|connect-peer`, `listpeers|list-peers`, `disconnect|disconnect-peer <node_id> [--force]` (ClientCommand 24, NL-152: `ClientApp.ParseDisconnectOptions`, `DisconnectPeerPrinter`; refused by the daemon while the peer has HTLCs in flight unless `--force`, and the node does not reconnect the peer until the next `connect` or restart), `shutdown|stop` (ClientCommand 39, NL-591/NL-592: `ClientApp.ParseShutdownOptions` (`--wait`, `--timeout <seconds>` (needs `--wait`, 1-`ShutdownDefaults.MaxWaitTimeoutSeconds` (86,400), the daemon's default 300 when unset), `--force`), `ShutdownPrinter` (the outcome, the busy counts per channel, the nearest HTLC expiry; `--force` prints the back-before-the-deadlines warning); the command exits 0 only when the node is stopping (an accepted plain/waited/forced shutdown), 1 on a refusal or a timed-out wait (`ClientApp.ExitCodeFor`, NL-594), `listforwards|list-forwards [count] [skip] [--since <time>] [--until <time>] [--status pending|offered|fulfilled|failed] [--channel <channel>]` (ClientCommand 40, NL-597: `ClientApp.ParseListForwardsOptions`, a time is Unix seconds or an ISO date, the channel a channel id or `blockxtxxoutput` scid, validated as a usage error before the IPC call; `ListForwardsPrinter` prints a block per forward — status, times, in/out channels by scid when known, amounts, fee, hash short form, failure code name — then the totals line with the fees earned and the refused-before-forwarding counters of NL-598); plain is refused by the daemon while HTLCs are in flight, otherwise the node refuses new activity and stops once it answered), `listchannels|list-channels [peer_id]`, `getaddress|get-address`, `walletbalance|wallet-balance`, `withdraw|sendcoins|send-coins <address> <amount_sat|all> [--sat-per-vb <n>]` (ClientCommand 25: `ClientApp.ParseWithdrawOptions` (the option also as `--sat-per-vb=n`, anywhere; 1-`MaxWithdrawSatPerVbyte` (1,000, the daemon's `WithdrawClientHandler.MaxSatPerVbyte`)), `WithdrawPrinter` (txid in display order, amount, fee with sat/kw and vB, change, inputs, anchors reserve, a line when bitcoind refused the send); `all` keeps the anchors reserve as change), `openchannel|open-channel <node> <sats> [push_sats]` (push below the channel amount, NL-301), `createinvoice|create-invoice|addinvoice <msat|any> [description] [expiry_seconds]`, `payinvoice|pay-invoice|pay <bolt11> [msat] [timeout_seconds] [--max-fee-msat <msat>] [--max-parts <n>] [--timeout <seconds>]` (exit code 1 when the payment failed; the options, also as `--option=value`, anywhere after the command, parsed by `ClientApp.ParsePayInvoiceOptions`: the per-call fee limit (0 allows only fee-free routes, NL-270), the most HTLCs in flight at once 1-`MaxPayParts` (128, the daemon's `PaymentSendOptions.MaxPartsLimit`; 1 never splits) and the timeout instead of the positional one (not both); the printer adds `Attempts: N HTLC(s), at most P in flight at once`), `listinvoices|list-invoices [count] [skip]`, `listpayments|list-payments [count] [skip]`, `forceclosechannel|force-close-channel <channel_id>`, `pendingsweeps|pending-sweeps [channel_id] [all]` (BOLT 5, ClientCommand 14/15; `all` includes the closed channels; `ParsePendingSweepsOptions`), `chainstatus|chain-status` (ClientCommand 16, NL-216: `ChainStatusPrinter`; exit code 1 while chain processing is halted), `listnodes|list-nodes`/`listgraphchannels|list-graph-channels` (17/18) and `getroute|get-route <node_id> <amount_msat> [--max-fee-msat <msat>] [--final-cltv <blocks>]` (ClientCommand 19, BOLT 7 G4-T4: `ClientApp.ParseGetRouteOptions`, `GetRoutePrinter`) and `describegraph|describe-graph [--channels] [--nodes] [--limit <n>] [--offset <n>]` (ClientCommand 20, BOLT 7 G5-T4: `ClientApp.ParseDescribeGraphOptions`, limit 1-1000, default 100; `DescribeGraphPrinter` prints the summary and one line per connection, then the pages in the `listgraphchannels`/`listnodes` format and the command for the next page), `exportchanbackup|export-chan-backup [channel_id] [--output <file>]` (ClientCommand 21, `ClientApp.ParseExportChanBackupOptions`; writes the encrypted backup to the file, else prints it as hex; `ExportChanBackupPrinter`) `verifychanbackup|verify-chan-backup <file> | --hex <backup_hex>` (22; `VerifyChanBackupPrinter`, exit code 1 when invalid) and `restorechanbackup|restore-chan-backup <file> | --hex <backup_hex>` (23; `RestoreChanBackupPrinter`, exit code 1 when a channel is `Failed` or `KeysMismatch`)). Invoice/payment amounts are in **msat** (`any` = no amount; `0` is a usage error); `openchannel` stays in sat. Number arguments are checked in `ValidateArguments` (usage error, exit 2) against the daemon's limits, so the user never gets an IPC error for them: list `count` 1-`MaxListCount` (1000, the daemon's `ClientRequestGuards.MaxPageSize`), payinvoice timeout 1-`MaxPayTimeoutSeconds` (300, `PayInvoiceClientHandler.MaxTimeoutSeconds`); keep them in sync. The default command is `node-info`. `payoffer|pay-offer` and `fetchinvoice|fetch-invoice` (BOLT 12, ClientCommand 29/30 provisional) share `ParsePayOfferOptions(args, payment, out error)` (`<offer> [amount_msat]`, `--quantity`, `--note`, and for payoffer the payinvoice limits) into the public `PayOfferArguments` that `NamedPipeIpcClient.PayOfferAsync`/`FetchInvoiceAsync` take; `PayOfferPrinter` prints both (exit code 1 when nothing was paid, the payment failed or no invoice was fetched).
- `Ipc/NamedPipeIpcClient.cs`: one typed method per `ClientCommand` (note `GetWalletBalance` lacks the `Async` suffix). The older ones are copies of the same template; `CreateInvoiceAsync`, `PayInvoiceAsync`, `ListInvoicesAsync` and `ListPaymentsAsync` use the private generic `SendRequestAsync<TRequest, TResponse>`, which new methods should use too. `SendAsync` opens a new `NamedPipeClientStream` for every call (2s connect timeout) and reads and writes the frames through Transport.Ipc's shared `IpcFraming` (NL-154; a 4-byte big-endian length prefix, 10 MB cap). If the response is an `IpcEnvelopeKind.Error` envelope, it throws `InvalidOperationException("IPC error {code}: {msg}")`.
- `Handlers/OfferCommands.cs` (wave B12 lane D): `createoffer|create-offer <amount_msat|any> [description] [--issuer <text>] [--quantity-max <n>] [--absolute-expiry <unix_seconds>] [--paths]` (an amount needs a description; options also as `--option=value`), `listoffers|list-offers [--active] [count] [skip]` and `disableoffer|disable-offer <offer_id>` (64 hex), parsed and run there (`ClientApp` only delegates); printers in `Printers/OfferPrinters.cs` (`OfferPrintFormat`); `ClientCommand` 26-28.
- `Handlers/PeerStorageCommands.cs` (wave lh1, NL-432): `listpeerstorage|list-peer-storage [node_id] [--blob]` (ClientCommand 32), parsed and run there (`ClientApp` only delegates); printer `Printers/ListPeerStoragePrinter` (channels unknown now are marked `UNKNOWN (restore it)` with a `restorechanbackup` hint; `--blob` prints each handed-back blob as hex).
- `Handlers/ChannelPolicyCommands.cs` (wave sp1 lane SP1-G): `setchannelpolicy|set-channel-policy <channel> [--fee-base-msat <n>] [--fee-ppm <n>] [--cltv-delta <n>] [--htlc-min-msat <n>] [--htlc-max-msat <n>] [--reset]` (ClientCommand 35; options also as `--option=value`; each value checked against its BOLT 7 wire width (u32 fees, u16 delta, u64 amounts), at least one value or `--reset`, never both) and `getchannelpolicy|get-channel-policy <channel>` (36); `<channel>` is a channel id (64 hex), `BLOCKxTXxOUTPUT` or the BOLT 7 u64; parsed and run there (`ClientApp` only delegates); printer `Printers/ChannelPolicyPrinter` (each value marked `(channel)` or `(node)`). `ListChannelsPrinter` prints the fundings (`Fundings:`, one block per funding: status and kind, outpoint in display order, capacity, depth or `unconfirmed`, SCID, and the `splice_locked` flags for splices) and the `Retired SCIDs:` (retired at / expires at height) after the channel fields, only when the daemon sent them (wave sp2, keys 23/24); it also prints the effective policy (`CLTV Delta:`, `HTLC (min/max):`, `(channel policy)` after the fee when overridden).
- `Handlers/BumpOpenCommands.cs` (lane dfrbf, NL-528): `bumpopen|bump-open <channel_id> <feerate_per_kw> [--contribution-sat <sats>]` (ClientCommand 38), RBF of an unconfirmed dual-funded open in either role (NL-530), parsed, run and printed there (`NamedPipeIpcClient.BumpOpenAsync`); feerate 253-250,000 sat/kw, contribution 0 to 21M BTC (0: an accepter that stops contributing; the daemon refuses it for the opener); tests in `Daemon.Tests/Ipc/Handlers/BumpOpenIpcHandlerTests`.
- `Handlers/SpliceCommands.cs` (wave SP1 lane SP1-E, splicing plan §3.10): `splicein|splice-in <channel_id> <amount_sat> [--feerate <sat_per_kw>]` and `spliceout|splice-out <channel_id> <amount_sat> [--address <address>] [--feerate <sat_per_kw>]` (ClientCommand 33/34), parsed and run there (`ClientApp` only delegates); options also as `--option=value`, anywhere; feerate 253-250,000 sat/kw (`MinFeeRatePerKw`/`MaxFeeRatePerKw`, the daemon's `SpliceCommand` bounds); `--address` only for spliceout (none = a new address of the node's wallet; the client cannot check an address, the daemon's splice service does). `Printers/SplicePrinter` prints the state (`Splice signed`/`Splice aborted`/`Splice in progress`), the txid (display order, already a string in `SpliceIpcResponse`), the new capacity and the failure reason; exit code 1 when the splice was aborted or carries a `FailureReason` (`SpliceCommands.IsSuccess`); a splice stopped at `CommitmentSigned` with its txid carries a `Note` (key 5) instead (`IsStoppedAtCommitmentSigned`: the daemon keeps it and completes it on the reconnection; printed as `Splice waiting for the peer to reconnect` with `Note:`). `bumpsplice|bump-splice <channel_id> <feerate_per_kw> [--max-fee-sat <sats>]` (ClientCommand 37, wave SPR lane SPR-B; `ParseBump`, `BumpUsage`; feerate 253-250,000 sat/kw, fee cap 1 sat to 21M BTC; `NamedPipeIpcClient.BumpSpliceAsync`) prints through `SplicePrinter(bump: true)` (`Splice RBF signed`/`aborted`/`in progress`).
- `Handlers/OpenChannelMessageHandler.cs`: parses `--public`, `--dual-fund`, `--v1` (NL-551: force v1; the daemon opens v2 by default when the peer supports dual funding and no push is given; refused together with `--dual-fund`) and `--no-wait`, sends `OpenChannel`, then long-polls `OpenChannelSubscription` until the state is `ReadyForUs`/`ReadyForThem` or Ctrl+C. NL-535: `RunAsync` (delegates for the two calls, a `TextWriter`; tests `Daemon.Tests/Client/OpenChannelCommandTests`) prints the funding txid as soon as it is published (a dual-funded open's response carries it, keys 1/2 of `OpenChannelIpcResponse`; a v1 open's comes with the first subscription answer), passes the txid it printed last with every subscription call (`KnownFundingTxId`, `ReportFundingChanges`) and prints each new attempt (`OpenChannelSubscriptionPrinter.Print(item, previousTxId)`: "The channel's funding transaction changed"); `--no-wait` returns once the first txid is printed, and Ctrl-C after a txid prints "Not waiting ...; the open continues on the node" and exits 0 (before any txid the cancellation is an error as before).
- `Printers/`: `IPrinter<T>` plus one `<Name>Printer` per top-level `*IpcResponse` (nested `PeerInfoIpcResponse` is printed inside `ListPeersPrinter`). There is no JSON output mode. `ListChannelsPrinter` and the invoice/payment printers take an optional `TextWriter` (default `Console.Out`) and write culture-invariant text (layout shared in `PaymentsPrintFormat`, times as `yyyy-MM-dd HH:mm:ss'Z'` UTC); `test/NLightning.Daemon.Tests/Client/PrinterSnapshotTests.cs` pins their output, so update a snapshot only on purpose. Every invoice starts with `Kind:` (`BOLT 11` followed by its `Bolt11:` string, or `BOLT 12` followed by `Offer Id:`, the SHA256 offer id as in `listoffers`; NL-454). Txids and block hashes are printed in display order (bitcoind/explorer, reversed bytes) through `DisplayOrder.ToHex`, never with `Hash.ToString()` (internal order, NL-303; `TxId.ToString()` prints the display order since NL-519, `ToInternalHex()` the internal one; `TxIdDisplayTests` pins both); a channel_id stays as is. DTOs that already carry a display-order string (close, force close, pendingsweeps: `PendingSweepsIpcResponse.ToDisplay` on the daemon side) are printed unchanged.
- `Utils/ClientUtils.cs`: `ShowUsage()`.
- Usage errors (NL-628): `ClientApp.WriteUsageError` writes the validator's message to stderr; a message that carries the command's own usage (`Usage: ...`) ends with a pointer to `nltg --help`, any other (an unknown command) is followed by the whole `ShowUsage()`. Keep `Usage: <command> ...` in a command's validation errors. An unknown `--kind` of `listaccountingevents` and `accounting report register` lists the valid kinds.

## Dependency rules
- Allowed references: `NLightning.Domain`, `NLightning.Transport.Ipc` (wire DTOs and formatters), `NLightning.Daemon.Contracts` (CLI parsing in `Helpers/CommandLineHelper.cs`, and `NodeUtils`/`NodeConstants` for `nltg.ipc`/`nltg.cookie`).
- Must NOT reference: Application, Infrastructure.*, Daemon, Persistence, Repositories, Serialization, or NBitcoin. The client is a thin shell over the IPC contract.
- `NLightning.Daemon` references this project, so never add a Client -> Daemon reference (that would be a cycle).

## Adding a new CLI command (the common task)
1. Add a `ClientCommand` value in `src/NLightning.Domain/Client/Enums/ClientCommand.cs`. Append only; values are on the wire.
2. Add `[MessagePackObject]` `<Name>IpcRequest` and `<Name>IpcResponse` in `src/NLightning.Transport.Ipc/Requests|Responses/` using `[Key(n)]`. Append keys; never reorder or reuse them.
3. If a new Domain value object crosses the wire, add a formatter in `src/NLightning.Transport.Ipc/MessagePack/Formatters/` and register it in `NLightningFormatterResolver`. If a DTO has a nullable struct property, also register a `T?` formatter (as done for `PeerAddressInfo?` and `CompactPubKey?`).
4. On the daemon side, add an `IIpcCommandHandler` in `src/NLightning.Daemon/Ipc/Handlers/` and register it with `AddSingleton<IIpcCommandHandler, X>()` in `src/NLightning.Daemon/Extensions/NodeServiceExtensions.cs`.
5. Here, add a `<Name>Async` method to `NamedPipeIpcClient`, following the existing template (Version=1, new CorrelationId, `GetAuthTokenAsync`, `Kind = IpcEnvelopeKind.Request`; some existing methods write the equivalent `Kind = 0`).
6. Add `Printers/<Name>Printer.cs : IPrinter<<Name>IpcResponse>`.
7. Add the `case` aliases in `ClientApp.RunAsync` and `ClientApp.ValidateArguments` (argument count), then update `ClientUtils.ShowUsage()`.

## Conventions
- File-scoped namespace (`NLightning.Client.<Folder>`). Preferred style: relative `using Domain.X;` / `using Transport.Ipc.X;` directives after the namespace line, System/third-party usings above it (some files, e.g. `Printers/NodeInfoPrinter.cs`, `Printers/WalletBalancePrinter.cs`, still use fully qualified `using NLightning.X;` above it).
- Root `.editorconfig`: naming rules are errors (`_camelCase` private fields, `s_camelCase` private statics), unused usings (IDE0005) is an error, `var` preference is a warning. CI (`.github/workflows/pr.yml`, `dotnet.yml`) runs `dotnet format --verify-no-changes`.
- Pass the `CancellationToken` through every call. Ctrl+C cancels `cts` in `Program.cs`.

## Build / run / test
- Build: `dotnet build src/NLightning.Client -p:MSBuildWarningsAsMessages=MSB4121`
- Run: `dotnet run --project src/NLightning.Client -- --network regtest listpeers`. This needs a running daemon and `~/.nltg/<network>/nltg.cookie`.
- Format: `dotnet format --verify-no-changes --exclude "**/BlazorTests/**"` (repo root).
- Tests: there is no Client test project. Client tests live in `test/NLightning.Daemon.Tests/Client/` (internals are visible via `AssemblyInfo.cs`). `dotnet test` discovers them; `dotnet run --project test/NLightning.Daemon.Tests -- -namespace NLightning.Daemon.Tests.Client` also works.

## Gotchas
- `CommandLineHelper` (in Daemon.Contracts) accepts `--network x`, `--network=x`, `-n x`, `--cookie x`, `--cookie=x` and `-c x`; only the separate-value forms consume the next argument. These options are skipped anywhere, including after the command, so they are never command arguments. Cookie dir precedence: `--cookie` arg, `--network` arg, `NLTG_COOKIE`, `NLTG_NETWORK`, then `~/.nltg/mainnet`.
- Frames are MessagePack with LZ4BlockArray compression (`Hash`/`TxId` are standard `bin 8` values).
- The protocol has no server push. Progress is reported by the client repeating the request (a long-poll).

## Onion routing (BOLT 4) hooks
This project has no onion or payment code. When BOLT 4 lands, expose it here with the 7-step recipe: e.g. `ClientCommand.PayInvoice`/`SendPayment`/`DecodeInvoice` (decode via `src/NLightning.Bolt11`, but on the daemon side, since Bolt11 depends on Infrastructure) and a `PaymentStatus` long-poll that follows the `OpenChannelMessageHandler` pattern. Map BOLT 4 failure codes (PERM/NODE/UPDATE/BADONION flags) to a structured error DTO or to `src/NLightning.Domain/Client/Constants/ErrorCodes.cs` rather than a plain string.

- `keysend <node_id> <amount_sat> [--tlv <type>=<hex>]... [--max-fee-msat <msat>] [--timeout <seconds>]` (ClientCommand 31, wave lh1 lane l3): `ClientApp.ParseKeysendOptions` into the public `KeysendArguments` for `NamedPipeIpcClient.KeysendAsync`; `--tlv` is repeatable (type >= 65536, never 5482373484, hex value, empty allowed, no duplicates, `TryParseCustomRecord`); printed by `PayInvoicePrinter` (exit code 1 when failed). `PaymentsPrintFormat` prints `Keysend: yes` and one `Custom Record: type=hex` line per record for payments and invoices, and a keysend record's Bolt11 line as `- (keysend)`.
- `payinvoice ... [--out <channel>] [--in <channel>]` (NL-609): `ClientApp.ParsePayInvoiceOptions` reads a channel id (64 hex) or a short channel id (`BLOCKxTXxOUTPUT`) into `PayInvoiceArguments.OutgoingChannel`/`IncomingChannel` (init properties, the record's positional members unchanged) and refuses the same value twice; `NamedPipeIpcClient.PayInvoiceAsync` takes them as optional trailing parameters. An invoice of our own is a rebalance over a circular route (`--in` pins the way back).

- Labels and tags (NL-602 A3-T1): `Handlers/LabelOptions` takes `--label <text>` and repeatable `--tag <key>=<value>` (also `--option=value`, anywhere after the command) out of the arguments of `createinvoice`, `payinvoice`, `keysend`, `createoffer`, `payoffer`, `withdraw` and `openchannel` (every alias, `IsLabelledCommand`) before the command's own parser runs, in both `ClientApp.ValidateArguments` and `RunAsync`, and checks them with the daemon's Domain rules (`SourceLabels.TryCreate`; a usage error names `LabelOptions.Usage`). The result is the public `LabelArguments` (label, sorted `k=v` tags, `TagsOrNull` for IPC), passed as the trailing optional `labels` argument of `NamedPipeIpcClient.CreateInvoiceAsync`/`PayInvoiceAsync`/`WithdrawAsync`/`KeysendAsync`/`PayOfferAsync`/`OpenChannelAsync` (after `ct`, like `OpenChannelAsync`'s existing flags) and of `OfferCommands.RunAsync`/`OpenChannelMessageHandler.HandleAsync`. `PaymentsPrintFormat.WriteLabels` prints `Label:` and one `Tag:` line per tag (nothing without them) for invoices, payments, offers and channels.

- `accounting prices import <file> [--currency <code>] | list [--since] [--until] [--limit] [--currency] | fetch --since <time> [--until <time>]` (ClientCommand 45 actions 10-12, NL-602 A3-T2): `Handlers/AccountingPricesCommands` (reached from `AccountingBooksCommands` through `case "prices"`; `ParseOptions`/`TryParseTime` are internal there for it). `import` reads the file on the client with the Domain `AccountingPriceCsv` parser, refuses it listing every bad line by number (nothing sent), and sends it in requests of `AccountingPricesIpcRequest.MaxRowsPerRequest` (10,000) rows, adding up the counts; `Printers/AccountingPricesPrinter`. Tests: `test/NLightning.Daemon.Tests/Client/AccountingPricesCommandsTests`.
- Accounting financial book (NL-602 A3-T6, `Handlers/AccountingBooksCommands`, `Printers/AccountingFinancialReportPrinter`): `accounting report <gains|unrealized|lots|unvalued|unclassified|risk>` and `report balance|income|register --book financial`, with `--currency <code>`, `--price <per BTC>` (balance sheet market value, lots, unrealized, risk), `--by month|quarter|year|total` (gains) and `--after <seq>[:<adjustment>]` (the financial register's cursor; the lots' is a lot id); `--currency`/`--price` on balance or income need `--book financial`. `accounting export --format ... --book financial [--currency <code>]`: the page loop passes `NextAfterAdjustment` back (a page may end inside one sequence's adjustments). The printer rounds fiat to the currency's minor unit (`MinorUnits` of the response) for display only.
