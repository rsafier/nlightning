## 0. Cross-cutting facts to know first

1. **Channel dispatch handles opening and normal operation.** `src/NLightning.Application/Channels/Managers/ChannelManager.cs` has cases for OpenChannel, AcceptChannel, FundingCreated, ChannelReady, FundingSigned and, since ABCD wave 1 (N6, a604dff), update_add/fulfill/fail/fail_malformed_htlc, commitment_signed, revoke_and_ack and update_fee (Open channels only; `NodeOptions.EnableHtlcs` gates them; not Open → warning + close; Failed → the stored error again). Since ABCD wave 2 `channel_reestablish` is handled (N7, 4ec83d3) and locked-in HTLCs go to `HtlcSwitch` (forward, final hop, fail back; ca87313). Each peer's channel messages run one at a time in arrival order under a per-channel lock, and every send goes through one ordered `PeerOutbox` per peer (NL-033, NL-193). Since ABCD wave 3 `shutdown`/`closing_signed` are handled too (N10, b38ce86), so no BOLT 2 channel message of a v1 channel falls to `default` any more (v2/interactive-tx messages still do: a channel-scoped `warning`, the peer stays connected). A message for a channel we don't know gets an `error` for that channel_id. Channel failures always carry their channel id, never the all-zero id (NL-203).
2. **Peer-level messages.** `src/NLightning.Infrastructure/Node/Services/PeerService.cs` handles `IChannelMessage`, `error`, `warning`, gossip (since gossip wave G-B 256/257/258 go to the graph ingress when the graph is enabled, 258 also to `ChannelUpdateService`, and `gossip_timestamp_filter(0, 0xFFFFFFFF)` is sent after init to `gossip_queries` peers; 259 is a channel message handled by `AnnouncementSignaturesMessageHandler`; 261/263 answered with empty replies; 265 ignored) and `stfu` (channel `warning` + disconnect, since we don't do quiescence). onion_message (513) is still unknown and dropped (odd).
3. **Unknown even message types throw on receive**, as BOLT 1 requires (`src/NLightning.Infrastructure.Serialization/Messages/MessageSerializer.cs`). The BOLT 7 types 256-265 are all registered now (NL-100), so gossip no longer kills peers. Malformed messages (unknown even TLV, wrong wire type) get a connection `warning` and the connection is closed (NL-207).
4. **All tests run in CI.** `dotnet test --filter 'FullyQualifiedName!~Docker'` runs 6780 tests per framework at `5bbfbb5` (no skips; net10.0, plus net11.0 when built with SDK 11) including Application.Tests (1362) and Daemon.Tests (348); `scripts/check-sln-configs.py` keeps it that way (NL-167). Docker (local only, OrbStack): 139 tests after gossip wave G-B (adds `Docker/Gossip/` 16 and `Onchain/OnchainWatchCatchUpTests`; green at `5bbfbb5` on net10.0 with SQL Server and the multi-node server-database theory skipped: LND suite 57, CLN 15, ABCD 3 x 10, on-chain 22 + 2 Explicit, gossip 16), 120 after gossip wave G-A (green at `164289a` on net10.0 with SQL Server skipped; the 4 `Explicit` BOLT 7 capture tests pass when run on purpose; the list below is the wave 6 breakdown, see root `CLAUDE.md` for the current one), 106 after wave 6, all green at `3ce3cad` on net10.0 and net11.0 when run from an SDK container with `--network host` (the host process cannot reach the container IPs, NL-276), except 2 `Explicit` ones: the BOLT2 Proofs N0/N1/N6-N10 against LND (incl. `ChannelSafetyFlowTests`, `FeeUpdateFlowTests`, `CooperativeCloseFlowTests`), the channel_update exchange, the multi-node harness, the Postgres/SQL Server round trips, `MppFlowTests`, `PaymentRetryFlowTests` and the simple-close proofs (LND suite 57), `Docker/Utils` (2), the CLN interop and close suites (17), the ABCD suite (10; `scripts/run-abcd.sh 3`) and the BOLT 5 suite `Docker/Onchain/` (20: O0 smoke 2 incl. the stale-SCID reorg case, O2 2, O3 4, O4 5, O5 4, O6 3; `scripts/run-onchain.sh`; `Explicit`: the two O5 by-hand variants).
5. **Onion core (M1+M2), error onions (M3) and M4 (forwarding, final hop, send) are done.** `Application/Payments/Switch/HtlcSwitch` forwards, receives and propagates upstream; `Application/Payments/Send/PaymentService` pays invoices directly or through route hints, with retries, a per-call fee limit and MPP splits (ABCD waves 2 and 6); the final hop receives basic_mpp sets (wave 6). The ABCD suite (LND → NLightning → NLightning → LND) is green. Sphinx construct/peel, hop payload parsing/validation and a persistent replay set are implemented from the spec (see the BOLT 4 table). The older LNBolt onion code was not ported.
